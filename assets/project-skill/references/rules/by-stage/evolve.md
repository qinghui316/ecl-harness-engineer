# Evolve Stage Rules

> Generated from `red_lines.yaml`. Do not edit this file directly.

## HR-06: Keep Record Types Separate

Integration and Evolution records are not Changes and never count toward the set of five Changes reviewed by Evolution.

**On violation:** Recompute the eligible set from unique Change records.

## HR-07: Count Only Qualified Changes

Evolution eligibility requires completed, validation-passed, evidence-complete, non-abandoned unique Changes.

**On violation:** Exclude the record and repair its evidence or status before recounting.

## HR-08: Review Every Five Qualified Changes

Create pending review state at five unevaluated qualified Changes; Changes one through four do not start Harness maintenance.

**On violation:** Leave ordinary work unblocked and restore the correct pending set of Change IDs.

## HR-10: Apply Accepted Evolution Without E2

After E1 approval, apply a proposal automatically only when every acceptance check passes. Unavailable independent review records a staged candidate as rejected and a candidate-free review as noop.

**On violation:** Do not record keep and preserve the pre-E1 Harness content digest.

## HR-12: Bound Historical Loading

Load archive summaries through generated indexes and read deeper history only for a named resume, review, failure, or evolution question.

**On violation:** Stop bulk loading and return to the smallest relevant summary set.

## HR-13: Keep Coordination Local

Do not introduce daemons, remote locks, cross-machine synchronization, automatic Git initialization, or automatic business merges.

**On violation:** Remove the unsupported mechanism and report the local-only boundary.

## HR-16: Verify Evolution Result

Keep and rejected require a candidate bound to the independent review; only keep applies it. Noop requires no candidate. Rejected and noop preserve the pre-E1 Harness content digest.

**On violation:** Reject the terminal result until candidate presence, review binding, and content digest agree.

## HR-18: Preserve Command Evidence Status

Commands remain configured, candidate, or executed with evidence; adapter defaults are never reported as configured project commands.

**On violation:** Downgrade the command to candidate or attach valid project evidence.

## HR-20: Keep One Rule Source

Edit red_lines.yaml only, then regenerate critical and by-stage Markdown; never hand-edit derived rule views.

**On violation:** Regenerate derived views and discard manual divergence.
